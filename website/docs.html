01 · File actions

Open the radial menu on a file

Drag a file in Finder and pause — the radial menu appears at the cursor. Move onto an action sector and release to run it; move back to the hub or out of the wheel to cancel.

If you’d rather not drag, choose “Services → Open Kodeoff radial menu” from the file’s context menu in Finder. If the service item hasn’t appeared after a fresh install, log out of macOS and back in, then check again.

Since v0.1.7 there is an optional Finder long-press entry: enable it in Settings → Interaction → Open radial menu (off by default); it needs the accessibility permission and has not been fully validated on real hardware. The plain drag entry needs no extra permission. See the next section for enabling the Finder context menu.

Finder context menu

Put Kodeoff into /Applications and launch it once, then enable Kodeoff under System Settings → General → Login Items & Extensions → Finder Extensions. On some system versions this lives under System Settings → Extensions → Added Extensions. First launch shows a guide too.

In empty space you can create files in seven formats, copy the current folder path, or paste cut items; with files selected you can copy path and file name, move, copy, cut, send, share, or open the radial menu. Adjust visibility and favorite folders under Settings → Menu actions.

Cloud folders such as iCloud Drive or OneDrive may not show this extension menu — use “Services → Open Kodeoff radial menu” instead. If the menu still doesn’t appear after an upgrade, restart Finder and check again.

Customize right on the wheel

Open the radial customization page in settings and drag an available action onto a target sector to replace it. Click a sector to see its current action and configuration; empty slots accept dropped actions too.

The wheel defaults to the glass theme; switch to light or dark in appearance settings. The trigger pause duration and radius control when the wheel appears.

02 · Screenshot annotation

Start a screenshot and pick a region

The default shortcut is ⌥ ⌘ 4; you can also choose “Screenshot” from the menu bar. The first use needs the screen-recording permission in System Settings; the shortcut can be changed under Settings → Screenshot.

Drag to select a region, or click a recognized window. Arrow keys move the selection by 1 pixel, ⌘+arrow keys adjust one edge; Esc cancels. The menu bar also offers 3-second and 5-second delayed captures.

Selection is limited to the screen where it started — no cross-screen stitching yet. Low-resolution or virtual display environments show a notice; check your display settings.

Annotate and finish

Pick rectangle, ellipse, arrow, text, pen, numbering, mosaic, or eraser. ⌘Z undoes, ⌘⇧Z redoes. Press Enter to finish text input, then confirm the whole screenshot.

By default the finished shot is copied to the clipboard. If you prefer to pause and review each time, switch the after-capture action to the preview panel under Settings → Screenshot: save PNG, copy, send, share a link, or pin; click “100% original pixels” to inspect details, with scrolling for large images.

Pinned stickers & local history

Stickers stay on the desktop as small windows: drag to move, scroll to zoom, ⌘+scroll for opacity. Esc closes the current sticker and ⌘⇧Esc collapses all; you’ll be warned if the global shortcut is taken.

Menu bar → “Screenshot history…” lets you preview, copy, resend, share, or delete. It keeps the latest 30 by default, adjustable from 10–200 or off; turning it off clears local history immediately.

While signed in, screenshots are also sent to your phone by default. See Clipboard & screenshot sync for turning auto-upload off.

03 · Device transfer

Accounts & devices

Sign in with email and password; if you forget the password, reset it with an email verification code. The official service sends real verification emails — check your inbox and spam folder. Self-hosted services without email can add devices with an account code or pairing code.

The iOS App Store and TestFlight builds ship with the official HTTPS service built in, so regular users never enter a server address. The official service currently uses invite-code registration: creating an account needs a valid invite code plus an email verification code; existing accounts sign in with email and password directly. Dedicated development builds can connect to a local test service.

An account code lets a new device join the account — keep it like a password. A pairing code is a short-lived one-time credential. Each signed-in device gets its own credential, and unused devices can be removed from the device list.

Send files and folders

Choose “Send to phone” in the Mac radial menu, or send from the Finder context menu. Folders are zipped automatically; with multiple selections the relay send action is unavailable — compress them into one file first. Both ends must be signed in to the same account on the same relay.

For nearby Apple devices, AirDrop works with multiple files selected and no relay account.

Clipboard & screenshot sync

Plain text and links are sent manually via “Send clipboard to phone” from the Mac menu bar. Up to 64 KiB per send; oversized content is refused, not truncated. Empty content, clipboard items marked sensitive, and file references are not sent as plain text.

Screenshots have their own auto-sync switch under Settings → Screenshot, on by default. After signing in to the relay, a finished and copied screenshot is sent to the clipboard tab of your phone’s inbox; it is skipped when not signed in. Only the latest auto-synced screenshot is kept per sending device — a failed new upload never deletes the previous one.

To stop uploading screenshots, turn off “Auto-sync clipboard after screenshot”. Local copy, save, and manual sending stay available.

Receiving, cache & signing out

The iOS and web inboxes show the account’s files, clipboard text, and screenshots. Click a file to download and preview; download policy and cache retention days can be adjusted in settings.

The relay channel refreshes while the app is open. No new-file notifications arrive in the background; content syncs when you return.

Signing out clears local login state and this account’s inbox cache and tries to revoke the current device; files on the server for other devices are not deleted. After signing out offline, confirm and remove the old device from another one.

macOS credentials live in a fixed local file — the keychain is not read. iOS uses the system keychain; the web uses browser local storage. Switching services never sends old credentials to the new one.

04 · Link sharing

Create a share link from the app

After signing in to your relay account, choose “Share link” in the Finder context menu, or create from the screenshot preview or the screenshot history window. On success the link is copied and its validity shown; recipients don’t need your account — they open the link in a browser and download.

Link validity and remaining downloads are shown on the actual download page. Anyone holding a valid link can download — don’t forward it to people you don’t trust.

No-signup web sharing (paused)

This channel has been paused since 2026-10-20: the no-signup share page no longer accepts new uploads. Links created earlier still follow the original rules — valid for 24 hours and up to 20 downloads, then deleted automatically.

If an existing link contains violating content, report it via the reporting guide.

Install, permissions & troubleshooting

When something goes wrong

If connecting fails, first check that the service is running, that the device can reach the address, the HTTPS certificate, and local network permission. If login fails, confirm the account belongs to the current service; resetting the password invalidates old device logins.

Windows is currently an experimental local radial-menu build without phone transfer; screenshots are macOS-only for now; the iOS receiver needs a separate build. The iCloud channel has been retired.

You can report issues on the feedback page with your platform, version, reproduction steps, and the error text. Never post passwords, account codes, pairing codes, credential files, or private files.

Self-hosting notes ＋

Self-hosting

Self-hosting the relay suits people who manage their own servers. The server lives in server/ of the development repository; for local development run bash server/run-dev.sh, which uses a temporary data directory. Dedicated development or self-host builds can enable the connection configuration separately; the default UI does not show it.

A loopback address is reachable only from the machine running the server — a phone cannot connect to another computer through it. Real-device testing needs a reachable address configured into the build; cross-network services need HTTPS, a persistent data directory, mail configuration, and verified backup/restore.

The relay does not have end-to-end encryption yet. The server can read stored content; don’t treat a throwaway dev instance as a validated production service.
